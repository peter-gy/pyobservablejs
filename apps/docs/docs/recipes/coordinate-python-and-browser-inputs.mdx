# Coordinate Python and browser inputs

Interactive documents often need both kinds of control: host inputs that
live in Python, and Observable inputs that live in the browser. This recipe
drives one chart from each side and reads the browser-owned value back into
Python.

The marimo slider sets the _floor_ through a Python variable. The Observable
input sets the _gain_ entirely in the browser. The readout at the bottom is
a Python cell.

```marimo-config
requires-python = ">=3.11"
dependencies = ["pyobservablejs"]
```

```python
import marimo as mo
import observablejs as obs

floor_slider = mo.ui.slider(
    start=0,
    stop=40,
    step=5,
    value=10,
    label="Floor from Python",
)
```

```python marimo echo=false server-output=false
import marimo as mo
import observablejs as obs

floor_slider = mo.ui.slider(
    start=0,
    stop=40,
    step=5,
    value=10,
    label="Floor from Python",
)
```

```python
letters = [
    {"letter": "A", "frequency": 8.2},
    {"letter": "B", "frequency": 1.5},
    {"letter": "C", "frequency": 2.8},
    {"letter": "D", "frequency": 4.3},
    {"letter": "E", "frequency": 12.7},
]

notebook = obs.Notebook(
    obs.js(
        """
        const gain = view(Inputs.range(
          [1, 8],
          {label: "Gain in the browser", step: 1, value: 3}
        ));
        """,
        key="gain_control",
    ),
    obs.js(
        """
        Plot.barY(letters, {
          x: "letter",
          y: (d) => Math.max(d.frequency * gain, floor),
          fill: "letter",
          tip: {fill: "var(--marimo-island-background)"}
        }).plot({
          height: 260,
          y: {grid: true, label: "Scaled frequency"},
          color: {legend: false}
        })
        """,
        key="chart",
    ),
    variables={"letters": letters, "floor": 10},
)

full_view = notebook.view()
widget = mo.ui.anywidget(full_view)
```

```python
widget.value  # subscribe this cell to view synchronization

if full_view.has_rendered:
    gain_report = (
        f"Python reads `gain = {full_view.values.get('gain')}` "
        f"while it owns `floor = {notebook.variables['floor']}`."
    )
else:
    gain_report = "Waiting for the Observable view to render."
mo.md(gain_report)
```

## The division of labor

| Value     | Owner   | Path                                                               |
| --------- | ------- | ------------------------------------------------------------------ |
| `letters` | Python  | `variables=` at construction                                       |
| `floor`   | Python  | `update_variables` on every marimo slider change                   |
| `gain`    | Browser | `view(Inputs.range(...))`, then read through `values` after render |

Two rules keep this pattern predictable:

- **Keep each name owned by one side.** Python asserts `floor`. The browser
  asserts `gain`. When a name genuinely needs both owners, use the seeding
  contract in [Bidirectional inputs](../connect/bidirectional-inputs.mdx)
  deliberately.
- **Subscribe the reading cell.** The readout references `widget.value`, so
  marimo reruns it whenever the view synchronizes. Keep that reference in
  the reading cell to receive every synchronized update.

See [Python to Observable](../connect/python-to-observable.mdx) and
[Observable to Python](../connect/observable-to-python.mdx) for each
direction in isolation.
