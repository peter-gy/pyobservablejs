# Select cells and create subsets

Every view renders a selection of notebook cells plus the hidden dependency
closure those cells need. Three selection shapes cover all cases.

| Shape     | Call                                        | Cells rendered together                                        |
| --------- | ------------------------------------------- | -------------------------------------------------------------- |
| Full      | `notebook.view()`                           | Every notebook cell, subject to each cell's `display` setting. |
| Focused   | `notebook.cell("chart").view()`             | One selected cell. Its dependencies evaluate as hidden cells.  |
| Composite | `notebook.view(cells=["chart", "summary"])` | Several selected cells and their hidden dependency closure.    |

The composite example renders two selected cells. The data cell is not
selected, yet both selected cells use it through their dependency closure.

```marimo-config
requires-python = ">=3.11"
dependencies = ["pyobservablejs"]
```

```python
import marimo as mo
import observablejs as obs

notebook = obs.Notebook(
    obs.js(
        "const numbers = [2, 4, 8, 16];",
        key="numbers",
        display=False,
    ),
    obs.js(
        """
        Plot.barY(numbers, {
          x: (_, index) => index + 1,
          y: (value) => value * scale,
          tip: {fill: "var(--marimo-island-background)"}
        }).plot({height: 220, x: {label: "Position"}, y: {grid: true}})
        """,
        key="chart",
    ),
    obs.js(
        """
        html`<p>
          ${numbers.length} values,
          ending at <strong>${numbers.at(-1) * scale}</strong>.
        </p>`
        """,
        key="summary",
    ),
    variables={"scale": 2},
)

composite_view = notebook.view(cells=["chart", "summary"])
mo.ui.anywidget(composite_view)
```

## Selection inputs

`cells` accepts zero-based indices, Python cell keys, and `NotebookCell`
handles, in any mix. Explicit selections render in canonical notebook order.

```python
notebook.view(cells=[1, 2])
notebook.view(cells=["chart", "summary"])
notebook.view(cells=[notebook.cell(1), notebook.cell("summary")])
```

An empty selection, a duplicate selection, or a handle from another notebook
raises `ValueError`. Unknown keys raise `KeyError`, and out-of-range indices
raise `IndexError`. See [`Notebook.view`](../reference/notebook.mdx#create-views)
for the full validation contract.

## Cell handles

`NotebookCell` is a stable selection handle, available before render.

```python
chart_cell = notebook.cell("chart")  # by Python key
first_cell = notebook.cell(0)        # by index, negatives count from the end
all_cells = notebook.cells           # handles in notebook order

chart_view = chart_cell.view()
selected_cells = chart_view.cells
```

`key` comes from the Python-side `key=` cell option. `name` comes from the
Notebook Kit cell name declared in the source or set through `name=`. Both
are `None` when unset. `index` is the cell's zero-based notebook position.
`NotebookView.cells` returns the selected handles in notebook order.

## Composite view or separate views?

Both render several outputs. They differ in runtime ownership.

- A **composite view** evaluates the selected cells in **one runtime** with
  one graph snapshot and one readback. Use it when the outputs belong
  together in one place.
- **Separate views** evaluate in **separate runtimes** and own separate
  readback. Python variables and named browser inputs synchronize through
  the notebook. Use separate views when outputs belong in different
  frontend locations.

The [Split one notebook into several
views](../recipes/split-notebook-into-views.mdx) recipe mounts two focused
views side by side and drives both from one Python control.
