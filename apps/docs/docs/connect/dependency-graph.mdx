# Inspect the dependency graph

Every rendered view synchronizes a symbolic dependency graph: which cell
defines each variable, which cells read it, and the edges between them.
Python reads it through `NotebookView.graph`.

The live example renders a three-cell notebook, then draws its own
dependency graph with `graph.to_mermaid()` — the diagram below the widget is
produced by the library at runtime, not by this page.

```marimo-config
requires-python = ">=3.11"
dependencies = ["pyobservablejs"]
```

```python
import marimo as mo
import observablejs as obs

notebook = obs.Notebook(
    obs.js(
        """
        const cylinders = view(Inputs.select(
          ["All", ...new Set(cars.map((d) => d.cylinders))],
          {label: "Cylinders", value: "All"}
        ));
        """,
        key="cylinder_control",
    ),
    obs.js(
        """
        const filteredCars = cylinders === "All"
          ? cars
          : cars.filter((d) => d.cylinders === cylinders);
        """,
        key="filtered_cars",
        display=False,
    ),
    obs.js(
        """
        Plot.dot(filteredCars, {
          x: "weight (lb)",
          y: "economy (mpg)",
          fill: "cylinders",
          r: 4,
          opacity: 0.72,
          tip: {fill: "var(--marimo-island-background)"}
        }).plot({
          height: 300,
          color: {legend: true},
          x: {grid: true, label: "Weight (lb)"},
          y: {grid: true, label: "Fuel economy (mpg)"}
        })
        """,
        key="chart",
    ),
)

full_view = notebook.view()
widget = mo.ui.anywidget(full_view)
widget
```

## Walk the graph from Python

`graph` is a frozen snapshot of `CellInfo` records and `DependencyEdge`
records.

```python
graph = full_view.graph

graph.defines               # variables defined by cells in this view
graph.external_references   # names resolved outside the cells, e.g. "cars"

chart_cell = graph.cell_for_variable("filteredCars")
chart_cell.defines          # ("filteredCars",)
chart_cell.references       # names that cell reads

for edge in graph.edges:
    print(edge.source_id, "->", edge.target_id, "via", edge.variable)
```

`external_references` includes builtins the cells use, such as `cars`,
`Plot`, and `Inputs`, because no cell in the view defines them. That makes
the graph a quick answer to "what does this notebook need from its
environment?" — useful before overriding names with [Python
variables](python-to-observable.mdx).

`graph` requires a graph snapshot and raises
[`NotRenderedError`](../reference/values-and-graph.mdx#notrenderederror)
before one arrives. Guard with `has_graph_snapshot`. Each view snapshots the
cells _it_ evaluates: a focused view's graph contains the selected cell plus
its dependency closure, not the whole notebook.

## Export diagrams

`to_mermaid()` returns a [Mermaid](https://mermaid.js.org/) flowchart;
`to_d2()` returns a [D2](https://d2lang.com/) diagram. Both label nodes with
the cell index, its key or name, and its defined variables, and label edges
with the variable that links the cells:

```text
flowchart LR
  cell_0["Cell 0: cylinder_control, defines: cylinders"]
  cell_1["Cell 1: filtered_cars, defines: filteredCars"]
  cell_2["Cell 2: chart"]
  external_0["external: cars"]
  cell_0 -->|cylinders| cell_1
  cell_1 -->|filteredCars| cell_2
  external_0 -->|cars| cell_1
```

The real output also lists builtin external references; the snippet above is
abridged. Paste Mermaid output into any Mermaid renderer, a GitHub comment,
or `mo.mermaid(...)` as the live example does. Pipe D2 output to the `d2`
CLI for SVG:

```python
from pathlib import Path

Path("graph.d2").write_text(full_view.graph.to_d2(), encoding="utf-8")
```

```sh
d2 graph.d2 graph.svg
```

See [Values and graph records](../reference/values-and-graph.mdx) for the
`NotebookGraph`, `CellInfo`, and `DependencyEdge` field contracts.
