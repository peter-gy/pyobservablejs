# Observable to Python

`NotebookView` synchronizes rendered values back to Python. Move the `gain`
control to update the browser readout and the Python cell that reads from the
same view.

```marimo-config
requires-python = ">=3.11"
dependencies = ["pyobservablejs"]
```

```python
import marimo as mo
import observablejs as obs

notebook = obs.Notebook(
    obs.ojs(
        'viewof gain = Inputs.range([0, 12], {value: 5, step: 1, label: "Gain"})',
        key="gain_control",
    ),
    obs.js("const doubled = gain * 2;", key="doubled", display=False),
    obs.js(
        'html`<p>Gain is <strong>${gain}</strong>. Doubled is <strong>${doubled}</strong>.</p>`',
        key="readout",
    ),
)

full_view = notebook.view()
widget = mo.ui.anywidget(full_view)
widget
```

```python marimo echo=false server-output=false
widget
```

```python marimo echo=false server-output=false
widget.value  # subscribe this cell to view synchronization

if full_view.has_rendered:
    synced = full_view.values
    message = (
        f"Python sees `gain = {synced.get('gain')}` "
        f"and `doubled = {synced.get('doubled')}`."
    )
else:
    message = "Waiting for the Observable view to render."
mo.md(message)
```

## Readback members

Readback belongs to the view whose browser runtime produced it.

| Member         | Contract                                                            |
| -------------- | ------------------------------------------------------------------- |
| `has_rendered` | Whether this view has synchronized a completed browser render.      |
| `values`       | Decoded values whose name has exactly one owning cell in this view. |
| `cell_values`  | One `CellValues` record per selected cell, in notebook order.       |

Reading `values` or `cell_values` before the view renders raises
[`NotRenderedError`](../reference/values-and-graph.mdx#notrenderederror).
Guard readback with `has_rendered`. A name produced by more than one selected
cell is omitted from `values` because it has no unique owner. `cell_values`
still reports it per cell.

```python
for record in full_view.cell_values:
    print(record.index, record.key, record.values)
```

## What comes back

Browser values decode to Python equivalents: `Date` becomes
`datetime.datetime`, `BigInt` becomes `int`, typed arrays become `bytes`,
`Map` becomes a list of tuples. Values without a faithful Python form, such
as DOM elements and functions, decode to descriptive strings. The full table
is in [Variables and
serialization](../reference/variables-and-serialization.mdx#browser-to-python-readback).

## Reacting to readback in marimo

marimo reruns a cell when a UI element it references changes. Reference the
wrapped widget's `value` in the reading cell so the cell reruns whenever the
view synchronizes new state. In plain Jupyter, readback is not push-based.
Read `values` when you next need it, or observe the underlying traitlets.

## Reading from a focused view

Each view synchronizes its own selected-cell values. A focused view evaluates
the selected cell's hidden dependencies while reporting values for the
selected cell:

```python
gain_view = notebook.cell("gain_control").view()
```

After an anywidget host mounts and renders `gain_view`,
`gain_view.values["gain"]` reads the value from its runtime. When the user
changes `gain` in either view, both
views converge through the notebook's synchronized input state. See
[Bidirectional inputs](bidirectional-inputs.mdx).
